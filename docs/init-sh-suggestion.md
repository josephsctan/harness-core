# Suggested Improvement: init-worker.ps1 Environment Bootstrap

**Source:** [Effective Harnesses for Long-Running Agents](https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents) (Anthropic, Nov 2025)
**Saved reference:** `inspiration/effective-harnesses-for-long-running-agents.md`

---

## `init-worker.ps1` — Environment Bootstrap Script

### The Gap

Harness-core relies on `CLAUDE.md` + the plan to orient a new agent session. This is sufficient for *reading context*, but it doesn't restore *runtime environment state*. An agent starting a new chunk must infer how to run the app, what env vars are needed, how to start services, and how to run tests — by reading docs, package.json, etc.

For complex stacks (e.g. a Vite dev server + API backend + Playwright), this inference costs tokens and introduces variance between sessions.

### The Suggestion

The **first chunk of a plan** should produce an `init-worker.ps1` in the **project repo root**. Subsequent chunks start by running it.

> **Project-specific:** `init-worker.ps1` lives in the project repo, not in harness-core. It encodes that project's deps, env vars, services, and test commands. Harness-core only needs to know to look for it and run it.

> **Platform note:** `init-worker.ps1` + `pwsh -File init-worker.ps1` is the Windows form. For cross-platform repos where Git Bash / WSL is guaranteed, `init-worker.sh` is equivalent.

**What `init-worker.ps1` should contain:**
```powershell
# Auto-generated by first chunk of <plan name>
# Restores the development environment for agent sessions.

# Verify working directory
Get-Location

# Install deps (idempotent)
npm install

# Confirm key env vars are set
if (-not $env:DATABASE_URL) { Write-Error "ERROR: DATABASE_URL not set"; exit 1 }

# Start background services (if needed)
# Start-Process npm -ArgumentList "run", "dev"

# Run smoke test to confirm environment is healthy
npm test -- --run
```

**Placement:** `<project-repo-root>/init-worker.ps1` (committed to the project repo).

### Justification

- Reduces token burn at session start — no need to re-read README or infer test commands
- Eliminates environment-variance bugs where one session runs tests differently than another
- Makes sessions truly self-contained: `pwsh -File init-worker.ps1 && <implement chunk>`
- Low cost to implement — first chunk writes it once, all subsequent chunks use it

### Change to `execute-chunk.js`

Add an optional pre-step in the implementer agent prompt:

```
Before beginning the chunk steps:
1. If init-worker.ps1 (or init-worker.sh) exists at the repo root, run it and confirm exit 0.
2. If it fails, write status: failed to next-chunk.md with the init-worker script output.
```

Add to the plan template (`docs/plan-template.md`):

```markdown
## Chunk 1 — Environment Bootstrap
- [ ] Write init-worker.ps1 at project repo root (install, env check, smoke test)
- [ ] Commit init-worker.ps1
- [ ] Verify init-worker.ps1 exits 0 cleanly
```
